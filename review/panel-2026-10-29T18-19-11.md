## 3. Should market numbers be masked until Qloo is live?  

**Recommendation:** **Show the market numbers now, hide the cultural column until the Qloo key works.**  

**Why this satisfies a Qloo CTO who already knows the data is yours:**

1. **Transparency of the baseline** – The market‑beta (SPY regression) is the *only* component that can be verified today. Displaying it demonstrates that the pipeline is functional, that the regression code runs, and that the desk can be audited end‑to‑end (data source → regression → UI).

4. **Future‑proofing** – When the key arrives, you only need to un‑hide the cultural column and populate it – no UI redesign. The “empty state” for cultural beta (greyed‑out bar, “—” value, tooltip “Waiting for Qloo data”) is already in place.  

If the CTO worries about *mis‑interpretation* (users might think the cultural signal is zero), add a small inline note next to the cultural header:  

> “Cultural β unavailable – awaiting data feed.”  

That note is a single line of text, no extra component, and it clarifies the state without hiding the market side.

## 4. Is ΔR² + flag + limits card enough for a quant judge?  

**Almost, but one more number adds decisive interpretability:** **“Information Ratio (IR) of the cultural signal.”**  

*What it buys:*  

- **Signal‑to‑noise**: IR = (mean excess cultural beta) / (standard deviation of that beta). It tells the judge whether the cultural factor is *consistent* enough to be useful, beyond a simple significance test.  
- **Comparability**: Quant judges can instantly compare the IR to typical market‑beta IRs (≈0.5–0.7) and decide if the cultural factor is worth a separate allocation.  
- **Robustness check**: A high IR with a modest t‑stat can still be attractive if the variance is low; conversely, a significant t‑stat with a low IR signals a noisy factor.  

**Implementation note:** Compute IR on the same 106‑week sample used for the regressions; display it in the stat strip next to ΔR² (e.g., “IR = 0.42”). This is a one‑line addition, no new UI hierarchy.
